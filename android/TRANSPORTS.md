# Android transport choices

The phone receiver speaks authenticated HTTP on port `8787`. Choose how the Mac
reaches it over 5G. Transport, Spotify control, and playout receipts remain three
independently verifiable layers.

| Route | Account | Own domain | Android VPN slot | Intended use |
| --- | --- | --- | --- | --- |
| Tailscale | Tailscale on Mac and phone | No | Yes | Private tailnet; simplest when no other Android VPN is required |
| Cloudflare named tunnel | Cloudflare | Yes | No, but an existing VPN/proxy must let Termux reach Cloudflare | Ordinary HTTPS hostname while another VPN may remain active |
| Cloudflare Quick Tunnel | No | No | No | Temporary test; URL changes and has no uptime promise |
| Same LAN | No | No | No | Installation and fault-isolation fallback |

The installation agent chooses Tailscale unless another phone VPN must stay
active; then it chooses Cloudflare. The human handles login, VPN consent, and
any domain purchase. HTTPS is required on a public hostname; HTTP stays inside
a trusted LAN or encrypted tailnet. The bearer token remains required everywhere.

## 1. Persistent HTTPS: Cloudflare named tunnel

This route keeps working when the phone leaves Wi-Fi and does not occupy
Android's single VPN slot. It needs a Cloudflare account, a domain managed by
Cloudflare, and a hostname such as `station-phone.example.com`. Domain purchase
is separate from the tunnel and may cost money.

Keep the receiver on loopback in
`~/.config/audience-of-one/phone.env`:

```sh
STATION_PHONE_BIND=127.0.0.1
STATION_PHONE_PORT=8787
```

Install and authorize cloudflared in Termux:

```sh
pkg install cloudflared
cloudflared tunnel login
cloudflared tunnel create audience-of-one-phone
```

The create command prints a tunnel UUID and writes a credentials JSON below
`~/.cloudflared/`. Route one hostname to it:

```sh
cloudflared tunnel route dns audience-of-one-phone station-phone.example.com
```

Create `~/.cloudflared/config.yml`, replacing both UUID occurrences and the
hostname:

```sh
mkdir -p ~/.cloudflared
umask 077
cat > ~/.cloudflared/config.yml <<'EOF'
tunnel: 00000000-0000-0000-0000-000000000000
credentials-file: /data/data/com.termux/files/home/.cloudflared/00000000-0000-0000-0000-000000000000.json

ingress:
  - hostname: station-phone.example.com
    service: http://127.0.0.1:8787
  - service: http_status:404
EOF
chmod 600 ~/.cloudflared/config.yml ~/.cloudflared/*.json
```

Validate locally before starting it:

```sh
cloudflared tunnel ingress validate
station-phone restart
curl -fsS http://127.0.0.1:8787/health
cloudflared tunnel --protocol quic --edge-ip-version 4 run audience-of-one-phone
```

Leave that last process running for the first test. From the Mac:

```sh
curl -fsS https://station-phone.example.com/health
```

Only after that returns `healthy`, set:

```sh
STATION_PHONE_MCP_URL='https://station-phone.example.com/mcp'
```

The `/health` endpoint contains no token, user data, programme text or audio.
The `/mcp` endpoint requires the long random bearer token generated by the phone
installer. The current client does not send Cloudflare Access service-token
headers, so putting an interactive Access login in front of `/mcp` will block
the station rather than secure it. Use TLS plus the receiver token for this
release and apply ordinary Cloudflare rate limits if desired.

### Start the tunnel after reboot

Once the foreground test passes, create a separate Termux:Boot script:

```sh
cat > ~/.termux/boot/audience-of-one-cloudflared <<'EOF'
#!/data/data/com.termux/files/usr/bin/bash
termux-wake-lock >/dev/null 2>&1 || true
while true; do
  cloudflared tunnel --protocol quic --edge-ip-version 4 \
    run audience-of-one-phone \
    >> "$HOME/.local/state/audience-of-one-phone/cloudflared.log" 2>&1
  sleep 5
done
EOF
chmod 700 ~/.termux/boot/audience-of-one-cloudflared
```

This restarts an exited connector, but Android can still kill the whole Termux
process family if its battery/background permissions are wrong. The system
settings in [the Android guide](README.md) are part of the runtime, not cosmetic
advice.

### Existing proxy or VPN

If V2RayNG or another VPN is always active, use its per-app routing to let Termux
reach Cloudflare directly. `cloudflared` talks to Cloudflare edge addresses,
not only your public hostname, so a hostname-only bypass rule may do nothing.
Test the actual connector log and public `/health`; a live PID with repeated
TLS/QUIC errors is `tunnel=down` wearing a convincing costume.

QUIC uses outbound UDP port `7844`. If the current mobile network blocks it,
test `--protocol http2`. Do not alternate protocols blindly: keep the one that
produces registered edge connections and a healthy public endpoint on the
network you actually use.

## 2. Private no-domain route: Tailscale

Install Tailscale on the Mac and Android phone, sign both into the same tailnet,
and confirm that the Mac can see the phone. No public hostname or inbound router
port is needed.

Find the phone's `100.x.y.z` Tailscale address in the Android app. In Termux,
edit `~/.config/audience-of-one/phone.env`:

```sh
STATION_PHONE_BIND=0.0.0.0
STATION_PHONE_PORT=8787
```

Still in Termux, restart the receiver:

```sh
station-phone restart
```

Now test from the Mac:

```sh
curl -fsS http://100.x.y.z:8787/health
```

Then set on the Mac:

```sh
STATION_PHONE_MCP_URL='http://100.x.y.z:8787/mcp'
```

The tailnet encrypts this HTTP path. Binding `0.0.0.0` also exposes the port on
the phone's current LAN interface, so keep the bearer token secret and do not
use this configuration on an untrusted LAN without an additional firewall.

Android normally permits one VPN service at a time. Tailscale may therefore
replace V2RayNG, another proxy VPN, or a corporate VPN. Tailscale's app-based
split tunneling controls which applications traverse Tailscale; it does not
create a second Android VPN slot. If the other VPN must remain active, prefer
the Cloudflare connector route.

Putting `tailscale.com`, `tailscale.io`, or their control-plane hosts into the
other VPN's DIRECT list may help Tailscale sign in or contact coordination
servers. It does not let both Android apps own `VpnService` simultaneously and
therefore does not solve the one-active-VPN conflict. Userspace networking is an
advanced alternative, not part of this phone quickstart.

## 3. Disposable rehearsal: Cloudflare Quick Tunnel

Quick Tunnel is useful for proving that mobile data can carry phone voice before
buying or moving a domain:

```sh
pkg install cloudflared
station-phone restart
cloudflared tunnel --url http://127.0.0.1:8787
```

cloudflared prints a random `https://...trycloudflare.com` URL. Test its
`/health`, then temporarily set the same URL plus `/mcp` on the Mac. The URL
changes whenever the command restarts; Quick Tunnels have no uptime guarantee
and are not the address for an unattended station.

## 4. Same-Wi-Fi fallback

Use this route to separate radio bugs from Internet/tunnel bugs. It requires a
trusted Wi-Fi network shared by the Mac and phone.

In `~/.config/audience-of-one/phone.env`:

```sh
STATION_PHONE_BIND=0.0.0.0
STATION_PHONE_PORT=8787
```

Restart the receiver. Find the phone's Wi-Fi IP in Android's current network
details, then test from the Mac:

```sh
curl -fsS http://192.168.x.y:8787/health
```

If it fails, verify that both devices are on the same non-guest network and that
client isolation is disabled. Do not open or forward port `8787` on the Internet.

Set temporarily:

```sh
STATION_PHONE_MCP_URL='http://192.168.x.y:8787/mcp'
```

LAN success proves the receiver and token path. It does not prove that the 5G
route, Spotify Connect cold start, or Android background survival works.

## Transport acceptance

For the selected away route, all five statements must be true:

1. `station-phone status` reports MCP and player up with a fresh heartbeat.
2. The Mac reaches `/health` through the selected route with Wi-Fi disabled on
   the phone.
3. `station say "5G line check." --phone --json` returns ordered voice start and
   finish receipts.
4. The same check works with the phone locked for five minutes.
5. After reboot, the route returns without manually reopening a Termux shell.

If 1 passes and 2 fails, debug transport. If 2 passes and 3 fails, debug the MCP
token/file/receipt path. If speech succeeds but music does not, debug Spotify
Connect separately. One green layer is not a group pardon.
